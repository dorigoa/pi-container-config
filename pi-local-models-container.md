# Pi with local models, sandboxed in a container (macOS and Linux)

*Pi 1.1.0 · Apple `container` 1.3.1 · macOS 27 · `pi-box` 1.2 — October 2026*

## Overview

```
host (Mac or Linux PC)
├── inference engine (llama.cpp, vLLM, …) on 127.0.0.1:8080   ◄─┐ OpenAI-compatible API
└── container ── Pi (coding agent) ─────────────────────────────┘
      sees only:  /work                = project folder
                  /home/dev/.pi/agent  = Pi config and sessions
```

Pi gives the model four tools (read, write, edit, bash) and has **no permission system**: every command runs with your privileges. That is why it's worth running it in a container. The model itself runs outside, in your inference engine.

| Path | Contents |
|---|---|
| `~/.pi/agent/models.json` | model config for Pi **without** a container |
| `~/pi-container/pi-box.conf` | `pi-box` defaults |
| `~/pi-container/agent/` | Pi config and sessions **inside** the container |
| `~/pi-container/image/Containerfile` | image recipe, generated by `pi-box` |

## 1. Pi directly on the host

**Install** (macOS/Linux). The installer pins dependencies and installs Node.js if needed:

```bash
curl -fsSL https://pi.dev/install.sh | sh
# or, with Node.js ≥ 22.19:
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

**Find the model id** exposed by your engine:

```bash
curl -s http://127.0.0.1:8080/v1/models   # copy the "id" field
```

**`~/.pi/agent/models.json`:**

```json
{
  "providers": {
    "local": {
      "baseUrl": "http://127.0.0.1:8080/v1",
      "api": "openai-completions",
      "apiKey": "local",
      "models": [{
        "id": "gemma-4-26b-a4b-it",
        "name": "Gemma 4 26B (local)",
        "reasoning": false,
        "input": ["text", "image"],
        "contextWindow": 32768,
        "maxTokens": 8192,
        "samplingParams": { "temperature": 1.0, "top_p": 0.95 }
      }]
    }
  }
}
```

- **`baseUrl`**: use `127.0.0.1` rather than `localhost`. Node may resolve `localhost` to IPv6 `::1`, where the server isn't listening.
- **`apiKey`**: required, even a dummy one; without it Pi hides the model.
- **`id`**: must match `/v1/models` exactly.
- **`reasoning`**: `true` for thinking models.
- **`contextWindow`**: must match the server (`-c` in llama.cpp, `--max-model-len` in vLLM).
- **`samplingParams`**: optional; passed to the server as is.

**Run:**

```bash
pi --provider local --model gemma-4-26b-a4b-it --thinking off
```

Inside Pi, `/model` switches model (`Ctrl+S` saves it as the default) and `/thinking` sets the level: `off`, `minimal`, `low`, `medium`, `high`, `xhigh` or `max`. Defaults can also go in `~/.pi/agent/settings.json` (`defaultProvider`, `defaultModel`, `defaultThinkingLevel`).

With **llama.cpp in router mode** (`llama-server --models-dir …`, no `-m`) you don't need `models.json`: run `/login llama.cpp` and then `/llama` to load models.

## 2. Container runtime (one-time setup)

### macOS: Apple `container`

Apple's open-source tool. It is **not preinstalled** and needs Apple silicon and macOS 26 or later. Each container is a lightweight VM, which isolates more strongly than Docker.

```bash
curl -fLO https://github.com/apple/container/releases/download/1.3.1/container-1.3.1-installer-signed.pkg
pkgutil --check-signature container-1.3.1-installer-signed.pkg   # must be "Apple Inc. - Containerization"
sudo installer -pkg container-1.3.1-installer-signed.pkg -target /
container system start          # answer Y to install the default kernel
```

Inside a container, `127.0.0.1` means the container itself. To reach the Mac's localhost, create a DNS name (`pi-box` also does this automatically):

```bash
sudo container system dns create host.container.internal --localhost 203.0.113.113
container run --rm alpine/curl curl -s http://host.container.internal:8080/v1/models   # test
```

This **disables iCloud Private Relay** and is **lost on reboot**; `pi-box` recreates it, asking for your `sudo` password.

### Linux: Podman

```bash
sudo apt install -y podman
```

Rootless Podman is preferred; `pi-box` falls back to Docker only if Podman is missing (the `docker` group is effectively root). On Linux the container uses `--network host`, so it reaches `127.0.0.1` directly.

## 3. `pi-box`: one-command launcher

```bash
sudo install -m 755 pi-box.sh /usr/local/bin/pi-box
cd ~/src/my-project && pi-box
```

On each run, `pi-box`:

1. Reads `pi-box.conf`; command-line options take precedence.
2. Auto-detects the model from `BASE_URL/models` if none is given.
3. Regenerates `models.json`, rewriting `localhost` to `host.container.internal` on macOS and to `127.0.0.1` on Linux.
4. On macOS, starts the container service and creates the DNS name if needed.
5. On Linux, applies `--cpus` and `--memory` only if the kernel supports them (see Troubleshooting). `--memory` comes with an equal `--memory-swap`, i.e. no extra swap.
6. (Re)builds the image when it's missing or when the recipe, base image or package lists have changed.
7. Starts Pi already connected to the model.

### Options

| Option | `pi-box.conf` key | Default |
|---|---|---|
| `-u, --base-url URL` | `BASE_URL` | `http://127.0.0.1:8080/v1` (as seen **from the host**) |
| `-m, --model ID` / `-n, --name` | `MODEL_ID` / `MODEL_NAME` | auto-detected / = id |
| `-c, --ctx N` / `-o, --max-tokens N` | `CONTEXT_WINDOW` / `MAX_TOKENS` | `32768` / `8192` |
| `-r, --reasoning on\|off` / `-t, --thinking LEVEL` | `REASONING` / `THINKING` | `off` / `off` |
| `-i, --images` | `IMAGES` | `false` |
| `--temperature`, `--top-p`, `--top-k` | `TEMPERATURE`, `TOP_P`, `TOP_K` | server defaults |
| `--api-key KEY` | `API_KEY` | `local` |
| `-p, --project DIR` | — | current directory |
| `--cpus N`, `--memory M` | `CPUS`, `MEMORY` | `4`, `4g` (`""` = no limit) |
| — | `BASE_IMAGE` | `node:24-slim` |
| — | `APT_EXTRA` / `PIP_PACKAGES` | extra Debian / pip packages |
| `--rebuild` | — | rebuild the image from scratch (no cache) |
| `--build-only` | — | build if needed, then exit |
| `--shell` | — | open bash instead of Pi |
| `--dry-run` | — | show `models.json`, build args and command; run nothing |
| `--reset-config` | — | rewrite `pi-box.conf` with defaults (keeps a backup) |
| `-- …` | — | pass arguments to Pi, e.g. `-- --continue` |

`pi-box` refuses to mount your home directory or `/` as the project unless you pass `--force`.

```bash
pi-box -m gemma-4-26b-a4b-it -i -c 65536                       # multimodal model, 64K context
pi-box -u http://192.168.1.20:8000/v1 -r on -t high -p ~/src/x  # remote thinking model
pi-box --rebuild --build-only                                   # fresh image, don't start Pi
```

Sessions persist in `~/pi-container/agent/sessions/`.

## 4. The development image

`Containerfile` is regenerated on every build, so don't edit it by hand. Add packages through `APT_EXTRA` and `PIP_PACKAGES` in `pi-box.conf`; the next run detects the change and rebuilds.

| Area | Included |
|---|---|
| Tools | git, ripgrep, fd, curl, wget, jq |
| C/C++ | gcc/g++, clang, cmake, ninja, ccache, autotools, gdb, lldb, valgrind, clang-format, clang-tidy |
| C/C++ libraries | Boost, Eigen, fmt, spdlog, nlohmann/json, GoogleTest/GoogleMock, OpenSSL, zlib, libcurl, SQLite, SDL2 |
| Python (Debian packages) | numpy, scipy, matplotlib, pandas, sympy, scikit-learn, seaborn, networkx, pygame, Pillow, requests, PyYAML, BeautifulSoup, lxml, pytest, logzero |
| Python (pip) | ruff, mypy, rich, tqdm, click, httpx, ipython |

- **Scientific libraries come precompiled from Debian** for arm64 and x86_64, so the build never compiles anything.
- **`/opt/venv`** is a virtual environment that sees the Debian libraries and accepts `pip install`, which Debian blocks system-wide. It is already on `PATH`.
- **No display**: pygame uses the dummy video driver and matplotlib renders to files. Run games on the host to see their window.
- **User `dev`** has your host UID, so files created in the project are yours.
- **Anything installed during a session is lost on exit**, because the container is removed. Add it to the package lists to keep it.

## 5. What the container protects

| Protected | Not protected |
|---|---|
| Your home directory and system: Pi only sees the project and its own config | The project itself: Pi can delete or break it, so keep it in `git` |
| Privileges: non-root user; on macOS also a separate VM | Network: full Internet/LAN access, and all of the host's localhost services (macOS via `host.container.internal`, Linux via `--network host`) |

In short, it guards against destructive mistakes, not against data exfiltration.

## 6. Troubleshooting

| Symptom | Fix |
|---|---|
| Model missing from `/model` | `apiKey` missing, or `id` doesn't match `/v1/models` |
| `connection refused` to `localhost` | use `127.0.0.1` |
| macOS: container can't reach the server after a reboot | the DNS name was lost; `pi-box` recreates it |
| Linux: `container create failed (no logs from conmon)` or `runc … memory.max: no such file` | The kernel's memory controller is off; on Raspberry Pi the firmware adds `cgroup_disable=memory` (check `/proc/cmdline`). `pi-box` skips the limit with a warning; set `MEMORY=""` to silence it, or append `cgroup_enable=memory cgroup_memory=1` to `/boot/firmware/cmdline.txt` (single line, back it up first) and reboot. |
| Replies truncated / context fills quickly | Match `CONTEXT_WINDOW` to the server. Pi reserves 16,384 tokens for replies (`compaction.reserveTokens` in `settings.json`); lower it for small contexts. |
| `pi --print` hangs in a script | add `</dev/null` |
| Manual edits to `~/pi-container/agent/models.json` are lost | it's regenerated on every run; edit `pi-box.conf` instead |

## 7. Verification status

- **Tested on real hardware**: Apple `container` 1.3.1 setup and container→host connectivity on a MacBook Air M5; Podman 5.4.2 on a Raspberry Pi 5, including the memory-limit failure that `pi-box` now handles.
- **Tested with simulated runtimes** (bash 5.2): all `pi-box` logic, including limit detection, build, rebuild and input validation. Pi 1.1.0 accepts the generated `models.json` and sends correct requests to a mock OpenAI server.
- **Tested on Ubuntu 24.04**, not inside the image: the package names, the Python stack (venv, pip, numpy/scipy, headless pygame) and a CMake project using all the C++ libraries with g++ and clang++.
- **Not yet tested**: a real build of the 1.2 image, `pi-box` with real runtimes end to end, and macOS's bash 3.2.
